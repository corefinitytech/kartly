## 2026-09-30 (sign-in fix)
Sign-in and sign-up never worked against the real database: Better Auth wrote its own string ids into uuid columns (session insert failed, shown as "Email or password is incorrect"), and without the `nextCookies()` plugin the session cookie set inside server actions never reached the browser. Added `advanced.database.generateId: "uuid"` and `plugins: [nextCookies()]`. Verified in a browser: /admin, prefilled demo admin, sign in, lands on /admin/orders.

Payments verified end to end locally with `stripe listen` (order marked paid by the verified webhook). Resend was rejecting every email because `EMAIL_FROM` used example.com: `.env.example` now shows a working sender, and the mailer logs Resend's error code (no addresses).

Files touched: src/lib/auth.ts, src/lib/mailer.ts, .env.example, CHANGELOG.md.

## 2026-09-30 (speed and checkout fixes)
Fixed order pages and payment confirmation: raw `db.execute` rows return timestamps as strings (Drizzle disables the pg date parser), so `.toISOString()` threw and `/api/orders/[number]`, `/status`, order history and the success page all returned 500. Added `src/lib/dates.ts` (`toIso`, tested) and used it everywhere, including the sitemap. Success page now reads the guest token before its first poll (no 404). Speed: every parameterised query took two database round trips because postgres.js `unsafe()` (used by Drizzle) defaults to unprepared; the client now prepares statements (also inside transactions), halving DB time app-wide. One shared, small, warm connection pool (new connections cost ~2.5 s; pipelining on one connection makes parallel queries one round trip). Add to cart is one SQL statement and returns the updated cart, so the client no longer refetches; cart quantity and remove update instantly and return the cart (quantity changes previously did not refresh totals). Page loads fetch the cart once instead of twice. Better Auth session cookie cache (5 min) for the storefront; the admin guard still checks the database. Place order no longer waits on expiry cleanup or re-reads the order three times. Vercel functions pinned to `cle1` next to Neon us-east-2. Migration 0003 made safe for databases that already had `sessions.user_agent` (it had blocked 0003–0005 on Neon). Demo admin seed (`npm run db:seed:admin`) and admin sign-in prefill in development. Unhandled API errors are now logged (type and message only).
